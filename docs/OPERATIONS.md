# GoodField リリース運用手順

更新日: 2026-07-26

## リリース前

1. Node.js 24とnpm 11を使用する。
2. `npm ci`を実行する。
3. `npm run release:check`を実行する。
4. `docs/RELEASE_NOTES.md`の既知差異と対象範囲を確認する。
5. ルールセットとカードプールの定数がリリース対象と一致することを確認する。

## ルールセット固定

- 保存試合には`rulesetVersion`と`cardPoolVersion`を必ず記録する。
- 再開時は保存値と実行サーバーの対応版が一致する場合だけ復元する。
- ルールまたはカードプールを変える変更では既存定数を書き換えず、新しい
  バージョン定数とゴールデンFixtureを追加する。
- 生成物の意図しない差分は`npm run check:generated`で拒否する。

## マイグレーション

現行の試合ジャーナルは`MATCH_JOURNAL_SCHEMA_VERSION = 1`、運用監査ログは
`OPERATIONAL_AUDIT_SCHEMA_VERSION = 1`である。

1. 永続データを読み取り専用スナップショットへ退避する。
2. 新コードで既存ジャーナルの復元テストを行う。
3. スキーマ変更時は旧版を直接上書きせず、旧版から新版を生成する変換を用意する。
4. 変換件数、失敗件数、ハッシュを記録し、失敗が1件でもあれば切り替えない。
5. 切り替え後も旧データは保持期間中、読み取り専用で残す。

## ロールバック

1. 新規コマンド受付を停止し、処理中のイベント列を永続化する。
2. 直前のアプリケーション版へ戻す。
3. その版が対応する`rulesetVersion`の試合だけを再開する。
4. 新版で作成され旧版が解釈できない試合は変換せず保留し、データを保持する。
5. `npm run release:check`と復元スモークを実行してから受付を再開する。

ロールバックで試合ジャーナルや監査ログを削除しない。秘密情報を運用ログへ
コピーせず、調査には匿名化された参照値を使用する。
