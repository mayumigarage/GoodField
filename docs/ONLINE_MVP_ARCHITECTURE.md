# GoodField 招待制オンラインMVP 運用境界

更新日: 2026-07-26  
対象: T-053～T-061

## 対象範囲

- 1ルームは2～9席、個人戦のみとする。HumanとCPUを混在できる。
- ホストは空席をCPUへ変更でき、CPU席を空席へ戻せる。Human席は本人の退出まで
  ホスト操作で上書きしない。
- 観戦はルーム作成時にホストが明示的に許可した場合だけ受け付ける。開始後の
  新規プレイヤー参加は禁止し、許可済みの観戦者だけを本人情報なしの投影へ接続する。
- 入力期限は既存仕様どおり15秒。期限切れまたは試合中の切断後はCPUが代行し、
  再接続だけではHumanへ操作権を戻さない。
- 公開マッチメイキング、恒久アカウント、課金、ソーシャルログイン、チーム戦、
  複数リージョンは対象外とする。

## ライフサイクルと期限

- 未開始ルームの有効期限は作成から2時間。
- ゲストセッションは発行から30分の短寿命とし、再参加または明示的なローテーションで
  新しいCookieを発行して旧セッションを失効させる。
- ホストの一時切断は5分待つ。期限内に戻らなければ、接続中で最も若い席のHumanへ
  ホストを移譲する。移譲先がなければルームを失効させる。
- 未開始の明示退出は席を空ける。ホスト退出時も同じ移譲規則を直ちに適用する。
  開始後の退出は試合参加者を削除せず、CPU代行と再参加情報を維持する。
- 失効ルームおよび開始済みルームの初期保持期間は24時間。T-056の永続ストアで
  保持期限後の安全な削除ジョブへ移す。

## 配置構成

初期運用は単一リージョン、単一の公開Originとする。

```text
Browser
  └─ TLS / HTTP + WebSocket
       └─ GoodField Node.js runtime
            ├─ static client assets
            ├─ room/session API
            ├─ authoritative match engine
            └─ PostgreSQL-compatible durable store
```

TLS終端はリバースプロキシまたはマネージドロードバランサーで行い、Node.jsプロセスへ
転送する。HTTPとWebSocketは同じOriginを使う。静的アセットは同じOriginから配信し、
Cookieを第三者コンテキストへ送らない。ルーム、参加者、試合、再接続カーソルは
PostgreSQL互換ストアへRevision付きで保存し、プロセス再起動時に復元する。

## 信頼境界と脅威モデル

サーバーだけが、ルール状態、乱数状態、全手札、招待コードのハッシュ、
セッションハッシュ、再参加トークンのハッシュを保持する。クライアント入力は
Actor、Revision、対象、カード所有権、MP、フェーズを毎回サーバーで再検証する。

| 脅威 | 対策 |
|---|---|
| Actor偽装・セッション固定 | 用途別の暗号学的セッション、ルーム/参加者への固定、再参加時の旧セッション失効 |
| Cookie窃取 | `HttpOnly`、`SameSite=Strict`、本番`Secure`、30分期限、ローテーション |
| CSRF | 変更APIで同一Origin検査とセッション別CSRFトークンを併用 |
| Origin偽装 | 本番の許可Originを完全一致で固定し、WebSocket upgradeにも適用 |
| 招待コード総当たり | 192bitコード、ハッシュ保存、参加APIのIP/ルーム別レート制限、失効・再発行 |
| 二重参加・連打 | 表示名正規化、再参加資格、`requestId`/`Idempotency-Key`、単一のルーム正本 |
| 同時開始 | `OPEN`から`STARTING`への先行遷移後に1回だけ試合作成 |
| 秘密情報漏洩 | プレイヤー別投影、観戦投影、レスポンス/イベントへPRNG・他人の手札を含めない |
| ログ漏洩 | 生Cookie、セッション、再参加トークン、招待コード、手札を運用ログへ記録しない |

招待コードは招待URLにだけ含める。ActorアクセストークンやセッションCookie、
再参加トークンはURLへ含めない。参加画面はT-057で招待コード交換後にURLを
`history.replaceState`で安全なルームURLへ置き換える。

## 設定と秘密値

| 設定 | ローカル | ステージング/本番 |
|---|---|---|
| `GOODFIELD_HOST` / `GOODFIELD_PORT` | `127.0.0.1:3000` | 配備環境が注入 |
| `GOODFIELD_PUBLIC_ORIGIN` | 未指定可 | HTTPSの公開Originを必須指定 |
| `GOODFIELD_COOKIE_SECURE` | `false` | `true` |
| `GOODFIELD_SESSION_SECRET` | 起動時一時値 | 32byte以上、Secrets Manager等から注入 |
| `GOODFIELD_ROOM_SECRET` | 起動時一時値 | 32byte以上、Secrets Manager等から注入 |
| `GOODFIELD_DURABLE_STORE_MODULE` | 未指定可 | 永続ストアfactoryモジュールを必須指定 |
| 永続ストアURL | 不使用可 | 秘密管理基盤から注入 |

`NODE_ENV=production`ではHTTPS公開Origin、両秘密値、永続ストアモジュールが欠けた
起動を拒否する。モジュールは同期トランザクション境界を持つ
`createGoodFieldDurableStore()`をexportし、試合とオンラインチェックポイントの両方を
同じPostgreSQLへ接続する。
秘密値はソース、配布物、イメージ、CIログへ保存しない。本番・ステージング・ローカルで
値を共有しない。

## 初期運用目標

- 同時100試合、同時900 WebSocket接続を初期負荷目標とする。
- 通常APIのp95を300ms未満、リアルタイムイベント配信のp95を500ms未満とする。
- 単一プロセス障害からの復旧時間目標は15分。進行試合を最新確定Revisionから復元する。
- ルームと試合ジャーナルは終了・失効後24時間、匿名化した運用メトリクスは30日保持する。
  生セッション、招待コード、再参加トークンは保存対象にしない。
