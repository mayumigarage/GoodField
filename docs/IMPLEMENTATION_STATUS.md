## 採用したプロジェクト判断

初期授与の乱数消費順は、席順で1枚ずつ配る処理を9巡行う。確率と結果を互換対象とし、
公式実装の未知の乱数列そのものは互換対象にしない。候補順は必ず安定IDまたは席順で
正規化し、同一シード・同一入力のイベント列を再現する。

オンライン入力期限は要求時刻から15秒、修行は期限なしとする。期限到達時は公開
`INPUT_TIMED_OUT`イベントで対象を切断状態かつCPU操作へ移し、期限切れ時点の保留入力を
CPUが通常のコマンド検証経路から継続する。CPU操作中の入力要求には人間用期限を付けず、
CPU同士の入力は人間待ちまたは試合終了まで連続処理する。期限到達後の人間コマンドは
拒否し、再接続の`PLAYER_CONNECTION_CHANGED`では接続状態だけを戻して操作権はCPUに保つ。

ターン終了処理は、守護神を席順で全員判定し、守護神攻撃の防御入力が完了した後も
残りの守護神処理を再開する。その後、手番プレイヤーの病を5%判定で悪化させ、
悪化後の段階に対応するダメージまたは回復を適用してから勝敗を確定する。
守護神行動は公式教典の42行動定義を正本とし、地球神の「もらす」は通常授与、
月神の「満月刀」は防御可能な守護神攻撃として扱う。

終末授与は通常神器75%、公式悪魔5種合計25%の絶対重みで抽選する。悪魔効果後も
同じ授与義務を維持し、通常神器を得た時点で完了する。イタズラマンは存在する
神器と習得済み奇跡から最大2個を無作為に除き、個別の除去内容は対象本人だけへ
配信する。悪魔で昇天した場合は未完了の授与義務を破棄する。

「売る」の補充は取引神器と商品神器の合計で1回とし、「買う」で移動した商品に
売り手側の補充は作らない。支払いは所持金、MP、HPの順とする。商品を移動してから
HP0、復活または昇天、勝敗、補充の順で解決するため、売却商品が太陽のお守りなら
移動先の復活に使用できる。「買う」は価格0でも確認を要求し、購入した未使用奇跡は
習得せず手札へ置く。商品提示イベントと確認用ビューは購入者だけへ公開する。

超常現象は10候補を等重みで抽選する。巨大なタライとブラックホールは生存者全員を
候補として対象を無作為決定する。金山は生存者1人へ所持金を集約し、共通の0～99制約を
適用する。磁気嵐は生存者ごとの手札枚数を維持したまま全神器を再配分し、配分内容を
サーバー限定イベントにする。日食は席順に未使用の守護神を割り当てる。

きのこ大発生は生存者の席順で1巡し、これを3巡する。各自動行動の開始時にGFを1増やし、
サーバーが公開可能な状態だけから攻撃、直接効果、祈る、捨てるを等重みで選ぶ。攻撃の
防御入力中はキューを停止し、解決後に同じ位置から再開する。自動行動同士の間には通常の
手番終了処理を挟まず、3巡終了後に現行手番の守護神・病処理を一度だけ実行する。

CPUの最小戦略は本人向け`GameViewState`とその`legalActions`だけを参照し、降参以外の
実行可能な行動、対象、防御をシード付きで選択する。購入確認は支払い可能なら承認し、
防御候補がなければ許す。CPUコマンドも`handleCommand`へ渡して人間と同じ合法性検証を
適用する。既定の判断シードは試合シード、プレイヤーID、Revisionから導出する。

強制神器除去と習得奇跡除去の個別内容は対象本人だけへ公開する。磁気嵐の再配分と
乱数状態はサーバーだけが保持する。昇天弓はHP0時に75%判定を行い、命中時は攻撃元へ
30ダメージを適用してから使用者の昇天を確定する。

リアルタイム同期の`eventSeq`は非公開イベントを含むグローバルカーソルとする。
各配信は接続者向けに投影したイベント列と最新スナップショットを含み、非公開イベント
だけで進んだ場合も空イベント列と新しいカーソルを送る。履歴は1試合512件を保持し、
差分を連続復元できない場合は完全スナップショットと直近の重要イベント最大12件へ
切り替える。接続者のプレイヤーID・観戦権限は同期ペイロードではなく認証層で確定する。

演出キューはサーバーの`eventSeq`を正本として整列・重複排除し、表示中でも最新
スナップショットを即時保持する。時計が大きく進んでも一度の更新で複数の表示段階を
飛ばさず、スキップは現在段階だけを完了させる。完全同期時は滞留した古い演出を破棄して、
サーバーが選んだ直近の重要イベントだけでキューを置き換える。
`OFFICIAL_WEB_2026_07_26`は開始6,000ms、行動由来の全表示段階500ms、
ローカル選択0msとする。CPU固有の待ち時間は設けず、GF更新の500ms段階を共用する。
操作プレイヤーの通常手番が開始した時点で、前のプレイヤーの行動プレビューは表示しない。

オンラインの入力カウントダウンはサーバーの`inputDeadlineAt`を表示にだけ用いる。
期限到達時にクライアントは既定行動を送らず、選択内容と再送用`commandId`を破棄して
サーバーの期限処理を待つ。再接続後も最新スナップショットの`controller`を正本とし、
CPU代行中なら接続済みでも人間向け入力を再開しない。修行の`null`期限にはローカル
タイマーを作らず、待機時間によって入力状態を変更しない。

結果画面は個人戦の試合全体の決着として表示し、操作プレイヤーが敗者でも見出しを
「敗北」へ変更しない。勝者がいる場合は「勝利」と勝者名、同一ターン複数敗北では
「引き分け」と「勝者なし」を表示する。最終盤面と本人の手札は背面に残し、ゲーム入力は
すべて無効化する。初回リリースは個人戦だけを対象とし、チーム戦固有の結果文言は
保留バックログとする。

防御要求または取引確認が他プレイヤーへ出ている間、入力当事者以外の生存中の人間UIは
`WAITING`ではなく`RESOLVING`として演出中表示にする。入力対象者だけが
`COMPOSING_REACTION`または`CONFIRMING_TRADE`へ入り、昇天済み本人と観戦者は
`SPECTATING`を維持する。

仕様受け入れE2Eは規範文書の受け入れ章から番号付きケースIDを抽出し、件数と採番を
テストで固定する。4人CPU完走と終末悪魔決着はルールエンジン、公開ビュー、
リアルタイム同期、UI状態機械、画面描画を連結して検証する。通常速度の基本攻防は
500ms段階と1,000ms結果保持を実時間で再生し、各段階を±120msで検証する。

ゴールデンシナリオは通常2人戦、GF.1の2人戦、GF.1の4人戦を全員CPU・固定シードで
最後まで実行し、`tests/fixtures/golden`へ保存する。`npm run generate:golden`で明示的に
更新し、`npm run check`では再生成結果との完全一致を検査する。ルールセットやカード
プールの更新でFixtureが変わる場合は、コマンド列、乱数ログ、イベント列、最終状態を
コード変更と同じ差分としてレビューする。

試合永続化は試合ごとの追記型JSONLジャーナルとし、メタデータ、ルールセット、
カードプール、シード、受理済みコマンド、完全イベント、最新サーバー状態を保存する。
ファイル名には生の試合IDを使わずハッシュを用いる。運用監査ログは試合ジャーナルから
分離し、拒否コマンド、同期失敗、反応連鎖の技術的打切りだけを記録する。試合、Actor、
Command、Attackの識別子は用途別ハッシュへ変換し、コマンド本文、表示名、手札、
カードID、シードは運用ログへ出力しない。

ローカル実行の試合ID、プレイヤーID、シード、Actorアクセストークンは
`node:crypto`の乱数から発行する。アクセストークンはハッシュだけをサーバー内の
認可索引に保持し、HTTPはBearer認証、ブラウザWebSocketはBearerまたは
`goodfield-token.*`サブプロトコルで既存のActor認証・試合認可へ接続する。
単一Node.jsプロセスが静的アセット、試合作成、コマンド、リアルタイム同期を提供し、
サーバー時計の定期処理でCPU手番とオンライン期限を継続する。

ローカルブラウザはActor資格と最後の`eventSeq`を同一Originのローカルストレージへ保持し、
再読込時に本人用スナップショットを取得してからWebSocketの差分同期へ戻る。コマンド拒否時は
最新スナップショットでUI送信ロックを解除し、通信中断時は再取得後に操作を復帰する。
WebSocketイベントは既存演出キューへ入り、内部盤面を即時同期しながら授与、悪魔、守護神、
災い、昇天を順番に表示する。ローカル資格はURLへ含めない。

オンラインMVPはHost、Participant、Spectatorで用途を分けた30分セッションを
サーバー発行Cookieへ保存する。本番Cookieは`Secure`、全環境で`HttpOnly`と
`SameSite=Strict`を使い、変更APIは許可Originとセッション別CSRFトークンを検査する。
Cookie、再参加トークン、招待コードはハッシュだけをサーバー索引へ保持し、Actor認可は
ルーム参加者から試合プレイヤーへサーバー側で対応付ける。

未開始ルームは2時間、ホスト切断猶予は5分、失効/開始済みデータの初期保持は24時間とする。
ホスト切断後は接続中の最若席Humanへ移譲し、候補がなければ失効する。開始操作は
`OPEN`から`STARTING`へ先に遷移し、同じ`requestId`は同じ結果へ収束する。
開始後はHuman参加を拒否し、作成時に許可された場合だけ観戦投影を発行する。
T-055時点のルーム正本はプロセスメモリ上であり、再起動復旧はT-056で永続化する。
